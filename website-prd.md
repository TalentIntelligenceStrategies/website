**Status:** v0.13 · 2026-05-06
**Owner:** Michael Hwang

## 1. What this is

The marketing surface of TIS — the public homepage today, multi-page site over time. Introduces the consultancy spine, surfaces the two commercial pillars (Licensing Platform, Patent Intelligence SaaS), and routes the four audience tones (Taiwan SMEs, foreign companies, VCs / PE, incubators) to deeper surfaces.

This folder is a **consumer** of the brand system in [`/brand/`](../brand/), not a source of truth. Tokens, components, voice, and identity all flow inward from there. If a page wants something the brand system doesn't yet provide, the brand `.md` files are edited first.

DAG: `/brand/design-tokens.md → /brand/components.md → /website/index.html`. Identity and voice pointers (`visual-guide.md`, `voice-and-messaging.md`) compose into the HTML the same way.

## 2. Why now

- The two existing preview HTMLs in `/brand/previews/` render the brand system in isolation; they aren't the marketing site.
- The Licensing Platform MVP is upcoming and the SaaS already has paying users — the homepage needs to exist as the discovery surface that routes both.
- The brand `.md` files are stable enough (tokens / components / voice all baseline or near-baseline) to be consumed.

## 3. Audience tones the homepage must serve

Per [`brand/voice-and-messaging.md`](../brand/voice-and-messaging.md) §6:

| Tone | Where they land |
|---|---|
| Taiwan SMEs going overseas | Licensing pillar — bundle pricing, jurisdictions, NPE deterrence framing |
| Foreign companies entering Taiwan | Licensing pillar — TW-specific bundles, COMPUTEX / launch context |
| VCs / PE doing IP due diligence | Patent Intelligence pillar — SABCD, pre-built reports, token economics |
| Incubators / accelerators | Patent Intelligence pillar — cohort scans, batch portfolio review |

The hero is a **3-slide auto-advance rotator** (6s per slide, dot tablist for manual control, hover-to-pause) — Licensing Platform → Patent Intelligence SaaS → Strategic positioning ("From defense to position"). The static-single-pillar variant from v0.12 was un-retired in v0.13: a third positioning slide was added so the rotator now also carries the consultancy-spine framing the v0.12 build had pulled out into Services / About copy. Each pillar still routes deeper — Licensing CTAs jump to `#products` (Licensing tab), Patent Intelligence CTAs to `#products` (PI tab), Strategic positioning CTAs to `#about`. The audience-tone routing in the table above is unchanged.

### 4.2.1 Section padding rhythm

The page uses two section padding sizes, with a third "stack-collapse" rule that keeps spacing rhythm even between them:

- `.section { padding-block: clamp(56px, 8vw, 104px); }` — the standard rhythm for content sections (Stats / Products / Reports / Press / About).
- `.section--tight { padding-block: 32px; }` (24px below `md` 768) — used by the Partner strip wrapper, where the strip itself owns most of the visual weight and only needs a thin breathing band.
- `.section--tight + .section { padding-block-start: 0; }` — when a regular section follows a tight one, drop the regular section's top padding so the tight section owns *all* the visible breathing room around its embedded element. Without this rule the page reads asymmetrically — hero-bottom (filled by the silver gradient) plus pill-top stack as ~32px of white, while pill-bottom plus stats-top stack as ~136px. The collapse closes the gap.

Currently triggered once on the homepage (Partner strip → Stat card grid). Keep the rule generic — any future tight-then-regular adjacency on this surface gets the same treatment for free.

### 4.4 Skeleton & accessibility

Page-level structures that don't render visually but anchor the document:

- **Skip link** — `<a href="#main" class="skip-link">Skip to content</a>` first child of `<body>`. Off-screen by default (`left: -10000px`), repositions to top-left on `:focus-visible` with `surface-inverse` background and `text-inverse`. Z-index 5000 (skip-nav layer per [`design-tokens.md`](../brand/design-tokens.md) §7.2).
- **Visually hidden h1** — `<h1 class="sr-only">TIS — Strategic patent intelligence, grounded in 170M patents</h1>` inside `<main>`, before the hero. The hero's pillar headlines are h2 — the page document outline still needs an h1, but the visible hero is rotating, so the canonical h1 lives in the screen-reader-only stack. `.sr-only` uses the standard 1×1 clip-rect pattern.
- **Landmarks** — `<header role="banner">` (top nav), `<main id="main">`, `<aside aria-label="Menu">` (mobile drawer), `<footer role="contentinfo">`. Sections with their own headings carry `aria-labelledby` to the heading id; sections without a visible heading (Hero, Partner strip) carry `aria-label`.
- **Live regions** — contact-form success block carries `role="status" aria-live="polite"` so the success message is announced after submit.
- **Reduced motion** — `@media (prefers-reduced-motion: reduce)` collapses all `transition-duration` and `animation-duration` to 0ms; the hero rotator stops auto-advancing (the dot tablist remains for manual control); the 3D card-strip backdrop's per-card breathing animation is suppressed; the IP intelligence drop popup overlay/card animations and the brand-select dropdown animation are disabled; the lang-toggle shimmer-cube overlay is hidden entirely.
- **Hero rotator semantics** — the slider carries `role="region" aria-roledescription="carousel" aria-label="TIS pillars"`; each `pillar-slide` is a `tabpanel` controlled by a `tab` dot with `aria-selected` reflecting the active state. Inactive slides carry `aria-hidden="true"` + `inert` so screen readers and keyboard users only see the active slide.
